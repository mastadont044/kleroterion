Draw

—

1. The block was named in advance

Before this draw ran, the block it would use was published. At that moment the block did not exist, so nobody could know its hash.

2. The block landed

Its hash is fixed by the chain and the same for everyone. Nothing here is generated by us.

3. Balances were read at that block

Every holder above the minimum, with the excluded addresses removed. The full list is published with the record.

4. The hash became a number

Hash, token address and draw number are hashed together, then taken modulo the total weight. Your weight is your balance.

5. Walking the holders

Holders sorted by address, adding up weights until the sum passes that number. Whoever it lands on wins.

6. Winner

Same input, same output, every time. Anyone can repeat this.

Winner
—

How to check this yourself

This page did not take the record's word for it. It downloaded the published list of balances, hashed the block hash together with the token address and the draw number in your browser, and walked the holders itself. The green badge above only appears when that result matches what was recorded.

If you prefer doing it outside a browser, the worker is a single Python file:

python draw_worker.py verify draws/1.json

Both paths do the same arithmetic:

target = keccak256(blockhash ‖ token ‖ draw number) mod total weight
winner = first holder, sorted by address, whose running total passes target

The only thing that could bend a draw is knowing the block hash before committing to the block. That is why the block number is published while the block is still in the future.
